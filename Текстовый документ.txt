Создание фотоблога на Hugo с вложенными галереями — задача, которая элегантно решается через правильную организацию контента. Ниже — полная инструкция, основанная на возможностях Hugo и проверенных темах.
📁 Основы: структура проекта и Page Bundles

Ключевой концепцией для галерей в Hugo являются Page Bundles — папки, которые содержат контент и связанные ресурсы (изображения) вместе .

Существует два типа бандлов:

Leaf Bundle (листовой) — папка с файлом index.md и изображениями. Не имеет потомков, отображается как отдельная галерея или страница .

Branch Bundle (веточный) — папка с файлом _index.md, может содержать вложенные бандлы. Отображается как список альбомов/галерей .

Для вашей задачи (вложенные галереи) идеально подходит структура, где раздел галереи — это Branch Bundle, а вложенные альбомы — Leaf Bundles или другие Branch Bundles.

Пример структуры для раздела «Галерея» с подгалереями:
text

content/
├── gallery/                    # Branch Bundle (раздел галереи)
│   ├── _index.md              # Страница-список всех альбомов
│   ├── animals/               # Подгалерея (Branch Bundle)
│   │   ├── _index.md          # Список альбомов внутри animals
│   │   ├── cats/              # Leaf Bundle (конкретная галерея)
│   │   │   ├── index.md
│   │   │   ├── cat1.jpg
│   │   │   └── cover.jpg
│   │   └── dogs/
│   │       ├── index.md
│   │       └── dog1.jpg
│   └── nature/                # Ещё одна подгалерея
│       ├── _index.md
│       └── mountains/
│           ├── index.md
│           └── peak.jpg
├── blog/                      # Раздел блога
│   ├── _index.md
│   └── my-first-post.md
├── about.md                   # Страница «Обо мне»
└── _index.md                  # Главная страница

⚙️ Создание проекта и настройка
Шаг 1. Создание проекта

Выполните команды в терминале (используйте WSL или Git Bash на Windows):
bash

hugo new site photo-blog
cd photo-blog
git init

Шаг 2. Установка темы для галереи

Рекомендую использовать специализированную тему nicokaiser/hugo-theme-gallery, которая из коробки поддерживает вложенные альбомы, лайтбокс и адаптивную сетку .
bash

git submodule add --depth=1 https://github.com/nicokaiser/hugo-theme-gallery.git themes/gallery

Шаг 3. Настройка hugo.toml
toml

baseURL = 'https://example.org/'
locale = 'ru-ru'
title = 'Мой фотоблог'
theme = 'gallery'

# Настройка меню
[menus]
  [[menus.main]]
    name = 'Главная'
    pageRef = '/'
    weight = 10
  [[menus.main]]
    name = 'Обо мне'
    pageRef = '/about'
    weight = 20
  [[menus.main]]
    name = 'Блог'
    pageRef = '/blog'
    weight = 30
  [[menus.main]]
    name = 'Галерея'
    pageRef = '/gallery'
    weight = 40

Меню в Hugo можно определять централизованно в конфигурации, используя pageRef для внутренних страниц .
🖼️ Настройка галереи с подгалереями
Раздел галереи (Branch Bundle)

Создайте файл content/gallery/_index.md:
markdown

---
title: "Галерея"
description: "Мои фотографии по категориям"
---

Этот файл будет использовать шаблон list и автоматически отобразит все вложенные альбомы (бандлы, содержащие изображения) .
Подгалерея (вложенный Branch Bundle)

Создайте content/gallery/animals/_index.md:
markdown

---
title: "Животные"
description: "Фотографии животных"
---

Hugo автоматически создаст страницу со списком вложенных альбомов (cats, dogs).
Конкретная галерея (Leaf Bundle)

Создайте content/gallery/animals/cats/index.md:
markdown

---
title: "Кошки"
date: 2024-03-15
description: "Портреты кошек"
cover: cat1.jpg
---

Мои любимые кошачьи портреты.

Затем просто скопируйте изображения в папку content/gallery/animals/cats/. Тема автоматически:

    Создаст миниатюры

    Определит обложку (файл, содержащий feature в имени, или первый файл)

    Отобразит галерею в виде сетки с лайтбоксом 

Управление обложками альбомов

По умолчанию обложкой становится первое изображение. Чтобы выбрать конкретное, используйте параметр front matter:
yaml

---
title: "Кошки"
resources:
  - src: cat1.jpg
    params:
      cover: true
---

Или просто назовите файл с feature в имени: feature-cat.jpg .

Создайте простой файл content/about.md:
markdown

Привет! Я фотограф-любитель. Здесь я делюсь своими работами и мыслями.

Эта страница не является Page Bundle и не будет отображаться в списке галерей .

yaml

💡 Альтернативный подход: AutoPhugo

Если вам нужна ещё более автоматизированная работа с подгалереями, рассмотрите тему AutoPhugo . Она позволяет:

    Помещать изображения в assets/NAME-OF-ALBUM/

    Автоматически генерировать миниатюры и полноразмерные версии

    Поддерживает multi-level album support — вложенные подгалереи создаются автоматически 

Установка:
bash

git submodule add https://github.com/corneliusdavid/autophugo themes/autophugo
echo "theme = 'autophugo'" >> hugo.toml

Создание альбома:
bash

hugo new animals/cats/_index.md

🚀 Сборка и публикация
Локальный запуск
bash

hugo server -D

Флаг -D включает черновики (draft) для предпросмотра .
Финальная сборка
bash

hugo

Все файлы будут сгенерированы в папку public/, готовую для загрузки на любой хостинг (Netlify, Vercel, GitHub Pages) .
⚠️ Важное замечание о форматах изображений

Тема nicokaiser/hugo-theme-gallery имеет известную проблему с WebP — при ресайзе через Go-реализацию изображения становятся тусклыми. Используйте JPEG или PNG .

Hugo говорит, что в файле content/gallery/Liminal/_index.md он начал читать YAML-заголовок (front matter), но не нашёл закрывающий разделитель --- до конца файла (EOF = End Of File).

Типичные причины ошибки

1. Забыт закрывающий ---

Плохо (нет закрытия):
markdown

---
title: "Liminal"

или
markdown

---
title: "Liminal"

Описание...

Хорошо:
markdown

---
title: "Liminal"
---

2. Открывающий --- написан с ошибкой

Например, в начале файла есть BOM, пробел или невидимый символ:
text

 ---
title: "Liminal"
---

Первый --- должен быть самой первой строкой файла, без пробелов, табов и BOM.

3. Используются неразрывные пробелы или другой дефис

Иногда при копировании из Word/веб-страницы символ - заменяется на – (en-dash) или — (em-dash). Визуально похоже, но Hugo не распознаёт. Проверьте в редакторе с подсветкой невидимых символов (в VS Code: View → Render Whitespace).

4. Смешаны --- и +++

Hugo поддерживает:

    YAML → обрамляется ---

    TOML → обрамляется +++

Нельзя начинать с ---, а заканчивать +++. Также нельзя использовать JSON-стиль с ---.

5. Файл сохранён в UTF-16 или с BOM

Особенно актуально на Windows. Пересохраните файл в UTF-8 без BOM (в VS Code внизу справа нажмите на кодировку → Save with Encoding → UTF-8).
Пошаговая проверка

text

title: "Liminal"
---

Заодно — про регистр папки

В логе видно content\gallery\Liminal\, а ранее вы создавали content/gallery/animals/.... Если вы хотите использовать нижний регистр в URL (/gallery/liminal/), переименуйте папку в liminal. Hugo сохраняет регистр имени папки в URL, а Windows-файловая система регистронезависима, что иногда приводит к путанице при деплое на Linux-хостинг (GitHub Pages, Netlify). Лучше придерживаться единого стиля — маленькими буквами.
Если ошибка повторится с другими файлами

Hugo остановится на первом битом файле. После исправления Liminal/_index.md он может указать на следующий. Пройдитесь по всем _index.md и index.md в content/gallery/ и убедитесь, что каждый имеет корректную пару --- ... ---.
по адресу http://localhost:1313/ после запуска hugo server -D пишет зфпу тще ащгтв
Это не ошибка — просто перестановка раскладки

зфпу тще ащгтв — это то же самое, что Page not found, но набранное в русской раскладке при включённом английском языке.

Проверим:

    зфпу → page (з→p, ф→a, п→g, у→e)

    тще → not (т→n, щ→o, е→t)

    ащгтв → found (а→f, щ→o, г→u, т→n, в→d)

То есть Hugo отдаёт стандартную страницу 404 Page not found. Значит, на главной странице нет контента — тема его не находит.
Почему это происходит

Hugo сгенерировал сайт, но для главной страницы (/) нет шаблона и/или контента, который тема ожидает. Три самых вероятных причины:
1. Отсутствует content/_index.md (главная)

Тема nicokaiser/hugo-theme-gallery строит главную страницу из корневого бандла. Без него главная пустая.

Создайте файл content/_index.md:
markdown

---
title: "Мой фотоблог"
description: "Фотографии и заметки"
---

2. Нет ни одного альбома для показа на главной

Эта тема показывает на главной список альбомов, а не текст. Если раздел /gallery/ пуст или содержит только битый Liminal/_index.md — главная тоже отдаёт 404.

Убедитесь, что:

    content/gallery/_index.md существует и корректен;

    в content/gallery/ есть хотя бы один альбом с index.md и хотя бы одним изображением.

3. Сайт не собрался из-за предыдущей ошибки

Если Liminal/_index.md всё ещё битый (см. предыдущий ответ — незакрытый front matter), Hugo не собирает ни одной страницы, и localhost:1313 отдаёт 404 на всё.

Посмотрите вывод hugo server — если там снова ERROR ... EOF looking for end YAML front matter delimiter, значит проблема осталась. Сначала исправьте front matter, потом уже смотрите главную.
Что сделать по шагам

    Остановите сервер (Ctrl+C).

    Проверьте, что сборка проходит без ошибок:
    powershell

    hugo --debug

    Если увидите ERROR — исправьте файл, на который он указывает. Пока есть ошибка, главная будет 404.

    Создайте главную страницу content/_index.md:
    markdown

    ---
    title: "Мой фотоблог"
    ---

    Проверьте структуру — минимально должно быть так:
    text

    content/
    ├── _index.md              ← обязательно
    ├── about.md
    ├── blog/
    │   └── _index.md
    └── gallery/
        ├── _index.md
        └── liminal/
            ├── _index.md
            └── photo.jpg       ← хотя бы одно изображение

    Запустите снова:
    powershell

    hugo server -D

    Откройте http://localhost:1313/.

Если после этого всё ещё 404

Выполните:
powershell

hugo --debug --verbose

и посмотрите, какие страницы он реально сгенерировал. В конце вывода будет список вроде:
text

Rendered 8 pages in ...

Если страниц 0 или очень мало — контент не подхватывается (неправильная папка content, битый front matter, или тема не установлена корректно).

Также проверьте, что тема действительно стоит:
powershell

ls themes/gallery

Должны быть подпапки layouts, assets, i18n и т.д. Если папки нет или она пустая — git submodule add ... не сработал, и Hugo собирает сайт без темы, что тоже даёт 404.

Ключевое: string was used where mapping is expected — «использована строка там, где ожидается словарь (mapping)». И Hugo показывает только строки 1–2 — то есть он вообще не видит открывающий ---. Он воспринимает содержимое файла как обычный текст, а не как front matter.
Что именно не так

Судя по выводу, ваш файл сейчас выглядит так:
text

title:"Лиминальные пространства"
description:"Места где никого не осталось"

Нет открывающего --- в самой первой строке. Без него Hugo не понимает, что это метаданные, и пытается интерпретировать весь файл как YAML, натыкается на строку вместо словаря и падает.

Кроме того, есть вторая проблема: в YAML после двоеточия обязателен пробел. title:"..." — невалидно, нужно title: "...".
Как исправить

🔍 Почему это происходит?

Эта тема описывается как "very simple and opinionated" (очень простая и субъективная) и создана специально для фотоальбомов. Вот её основные правила:

    Отображаются только "пакеты страниц с изображениями": любой каталог, содержащий хотя бы одно изображение, отображается как альбом или галерея.

    Статьи без изображений не будут отображаться: файлы вроде about.md, которые не являются Page Bundle и не содержат ресурсов изображений, не отображаются в списке альбомов.

    Ваши статьи в блоге, скорее всего, не содержат изображений: если вы создали в content/blog/ несколько Markdown-файлов, но они не оформлены как Page Bundles (т.е. не находятся в отдельных каталогах с изображениями), эта тема не будет рассматривать их как "галереи" и не будет отображать в списках.

✅ Как решить?

У вас есть два варианта:

Вариант 1: Переключиться на тему, подходящую для блога
Если ваша главная цель — вести блог (текстовые статьи + вложенные галереи), рекомендуется использовать более универсальную тему, например PaperMod, Ananke, Blowfish и другие. Эти темы из коробки поддерживают списки статей и при этом могут настраивать страницы галерей.

Вариант 2: Сохранить эту тему, но "замаскировать" статьи блога под галереи
Если вы хотите остаться на текущей теме, но чтобы статьи отображались, нужно превратить каждую статью в Page Bundle с изображениями:

    Создайте для каждой статьи отдельный каталог, например content/blog/my-post/index.md

    Поместите в этот каталог хотя бы одно изображение (например, обложку cover.jpg)

🔄 Шаг 1: Установка новой темы

Существует два основных способа добавить тему в проект.

Способ А: Git Submodule (рекомендуется)
Этот метод позволяет легко обновлять тему и не захламляет основной репозиторий. Команды выполняются из корня вашего проекта:
bash

git submodule add https://github.com/автор/название-темы.git themes/название-темы

Например, для темы Ananke команда будет такой:
bash

git submodule add https://github.com/theNewDynamic/gohugo-theme-ananke.git themes/ananke
```[citation:3]

**Способ Б: Простое клонирование**
Если вы не хотите использовать Git-модули, можно просто клонировать репозиторий в папку `themes`:

```bash
git clone https://github.com/автор/название-темы.git themes/название-темы

Этот метод используется, например, в установке темы Archie.
⚙️ Шаг 2: Настройка конфигурации

После установки нужно указать Hugo, какую тему использовать. Откройте ваш файл конфигурации (hugo.toml или config.toml) в корне проекта и найдите строку theme =.

Измените её на название папки, которую вы создали в директории themes. Например:
toml

theme = 'ananke'

или
toml

theme = 'archie'
```[citation:3][citation:9]

Если вы используете Nix для управления зависимостями, тема подключается через `shellHook`, создавая символическую ссылку, например `ln -snf "${hugo-theme}" themes/m10c`, и в конфигурации указывается `theme = 'm10c'`[citation:1].

### 📦 Шаг 3: Установка зависимостей темы (если требуется)

Некоторые современные темы написаны с использованием CSS-фреймворков, таких как Tailwind CSS. Они могут требовать дополнительной сборки.

Например, тема **Hugo Noir** требует наличия **Hugo Extended** версии **v0.158.0** или выше. Если вы будете вносить изменения в её стили, потребуется установить Node.js и выполнить сборку CSS[citation:8].

### ⚠️ Шаг 4: Адаптация контента и конфигурации

Это самый важный этап. Разные темы ожидают разную структуру контента и разные параметры в конфигурации. То, что работало в старой теме, может не работать в новой.

*   **Параметры:** Проверьте раздел `[params]` в конфиге. Новая тема может требовать других полей (например, для автора, соцсетей, навигации)[citation:8].
*   **Меню:** Способы задания меню могут отличаться. Некоторые темы используют `[[menu.main]]` в конфиге, другие — файлы `data/`.
*   **Контент:** Структура `content` (типы страниц, таксономии) может отличаться. Например, тема может ожидать посты в `content/posts/`, а не в `content/blog/`.
*   **Специальные настройки:** У каждой темы есть свои уникальные параметры. Например, тема Shell требует настройки `[Params.Terminal]` для выбора цветовой схемы[citation:2]. Тема Lost использует `navMode` для переключения между вкладками и аккордеоном[citation:11].

Если вы хотите посмотреть, как это выглядит вживую, на странице темы есть ссылки на демо-версии .
